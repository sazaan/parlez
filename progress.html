2 · Admin panel
  • How it works: separate admin credential from env (ADMIN_USERNAME, bcrypt hash, ≥32-char session secret); login at /api/admin/login with constant-time checks, optional TOTP, a server-side admin_sessions row and a 15-min JWT in a scoped HttpOnly cookie; every write needs a CSRF token bound into that JWT plus a same-origin check. MFA secrets are Fernet-encrypted; changes revoke all sessions; config changes are audit-logged. Seven tabs: AI provider, course publishing, users, security/MFA, observability, change log, health.
  • Strengths: fails closed when config incomplete; keys never leave the server; provider endpoints fixed (SSRF-safe); publication gates the learner APIs; privacy-limited user directory and logs; good test coverage.
  • Gaps: single shared admin account (no roles/individual attribution or in-panel password rotation); MFA off by default with no documented recovery path and plaintext secret returned to the browser during setup; weak durable audit (failed logins only in stdout, no IP/session, silent 1000-row truncation, no filter/export); no active-session management UI; user admin is read-only; origin check depends on proxy headers; several read endpoints unthrottled; an SLO claims core API p95 ≤2 s while chat legitimately takes tens of seconds.

3 · French curriculum, materials & TEF/TCF
  • Framework: CEFR (Companion Volume 2020) is the right backbone — can-do descriptors across reception, production, interaction and mediation. The Council of Europe explicitly does not validate others' CEFR claims, so say "aligned to / based on CEFR descriptors", never "CEFR-certified".
  • Learning science: spaced practice (medium-to-large effect; revisit at 1/3/7/30 days), retrieval practice, interleaving (beats blocked grammar practice on delayed tests), comprehensible input paired with output + feedback, and task-based learning (meta-analysis d≈0.93; stricter reanalysis g≈0.61). Only ~6% of 50 reviewed apps explained why an answer was wrong — explanatory feedback is a differentiator.
  • Proposed spine: A1→B2 with sub-levels (A1.1–B2.3), ~60–80 guided hours/level; 8–10 mission-led units per level. Each unit: retrieval warm-up → authentic graded input (TV5MONDE/RFI) → noticing/focus on form → interleaved guided practice with explanations → real-world TBLT task → CAF feedback (complexity/accuracy/fluency) → SRS export + can-do self-check → cumulative return.
  • Exam tracks (branch at B1.2): TCF Canada — 2h47; 39 listening (35 min, audio once) + 39 reading (60 min) progressive MCQ, 3 writing tasks (60 min), 12 min speaking; IRCC NCLC 7 ≈ listening 458–502 / reading 453–498 / speaking 10–11 / writing 10–11. TEF Canada — ~2h55; 40 reading (60 min), 40 listening (40 min, forward-only), writing A ≥80 words/25 min + B ≥200 words/35 min, speaking 5 + 10 min; NCLC 7 on /699 ≈ 434 / 434 / 456 / 428. Critical: Express Entry uses the "Équivalence ancien score" column, not /699 — using the wrong column may cause refusal.
  • Legitimate sources: link out to official samples (FEI for TCF, CCI/Le français des affaires for TEF), TV5MONDE (TCF simulator + 680 practice questions, FEI-validated but not an official certificate), RFI, Lawless French, Kwiziq, Le Point du FLE, Anki export. Books: Inspire 1/2 (AF Kathmandu), Édito, Cosmopolite, Grammaire progressive du français, Bescherelle, Assimil, ABC TEF / TCF 250 activités, Hachette TEF workbook (2023+) — use as task-design models, never copy past papers or official PDFs.
  • Legitimacy workflow: provenance fields (source links, author, reviewer, credentials, version, exam-format version, verified-on date), qualified FLE reviewer + second reviewer for exam items, independent benchmarking of task levels, small pilot cohort, public changelog, claims register. Re-verify exam facts against IRCC/FEI/CCI every 90 days.

Sources: CoE CEFR · spacing meta-analysis · TBLT meta-analysis · IRCC language testing · FEI TCF Canada · CCI TEF Canada · TV5MONDE TCF · AF Kathmandu

4 · Chatbot audit — probable root causes found
  • P0 · reasoning budget: the default nemotron-3.5-lightning-30b-a3b is a reasoning model whose thinking shares max_tokens with visible output. The app hardcodes max_tokens: 2048, sets both temperature and top_p, never disables thinking or sets reasoning_budget, and never inspects finish_reason or Accept/stream. Result: empty/truncated answers reported as 200 successes — the failure is invisible in metrics.
  • P0 · lesson content thrown away: /api/chat carefully builds lesson_ctx (vocabulary, grammar, dialogue, exercises, cultural note), but build_system_prompt only uses title/description/objectives while instructing the model to "show the vocabulary and grammar content from the lesson data". The model never sees it — the most direct cause of bad lesson-mode answers.
  • P1 · new users misclassified: empty exercise history yields overall_accuracy: 0, so every first-time learner is told "30% French / 70% English" and given 4 simpler exercises, contradicting the intended 40% base ratio.
  • P1 · budget not durable/atomic: usage is incremented in the in-memory user blob and only saved on success; concurrent chats lose updates, failures are free, the 429 message says UTC while the code uses local date, and whole-blob rewrites can lose messages/XP.
  • P1 · context & latency: ~4.9k chars of always-on format spec plus a demand for 4 exercises pushes output past 2048 tokens; 3 retries × 60 s with 2/4 s backoff gives ~3 min with no overall deadline or fallback; the browser fetch has no timeout, so it looks hung.
  • P2 · safety/observability: UI never sends mode/lesson_id/scenario_id, so keyword heuristics misroute; only the last 15 raw messages are sent; guardrails are prompt-only; finish_reason, prompt size and budget rejections are not instrumented; tests cover only the happy path.

5 · Real-time conversation & interactivity
  • What winners do: Duolingo Max uses human-written, linguist-reviewed Video Call and Roleplay scenarios with transcripts and feedback; HelloTalk/Tandem add live voice rooms for the "freeze with real people" gap. Generic chatbots lack pedagogical scaffolding — graded vocab, corrections, curriculum alignment.
  • Latency is the product: users notice ~800 ms round-trip; a typical budget is STT 350 ms + LLM first token 375 ms + TTS first byte 100 ms ≈ 1.1 s mouth-to-ear. Show an interim transcript, a "thinking" beat, support barge-in, keep beginner turns to 10–20 s, always offer "type instead".
  • ASR path: start with browser Web Speech API (free, ~15 lines) — but audio goes to Google/Apple, Firefox is effectively unsupported, sessions need an onend restart loop. Later: faster-whisper / whisper.cpp / Whisper-Streaming self-hosted, or Deepgram/AssemblyAI streaming (~150 ms, semantic end-of-turn).
  • TTS path: browser speechSynthesis first; then ElevenLabs (~75 ms streaming), Cartesia, OpenAI or Google TTS. Cache repeated lines.
  • Pronunciation: Azure Speech Pronunciation Assessment (word/phoneme accuracy, fluency, prosody) or Speechace (CEFR-style scores). Cheap MVP: ASR transcript vs target sentence with a word-level diff.
  • Privacy/consent: voice is biometric-adjacent; explicit consent, retention/deletion policy, no raw-audio storage by default, captions and keyboard controls always.

Sources: Deepgram voice-agent architecture · MDN SpeechRecognition · AssemblyAI Web Speech guide · Duolingo Max · Azure pronunciation assessment · Speechace

7 · Payments (Nepal first)
  • Nepal rails are wallet/QR, not Stripe-like: settlement in NPR only; generally no webhooks, no subscription engine, no automatic refunds. Verification is a server-to-server status lookup after a browser redirect — never trust the browser return.
  • Start with Khalti + eSewa (dominant wallets, self-serve/public sandboxes). Khalti ePayment: initiate → pidx → redirect → lookup; only Completed counts; amount in paisa. eSewa ePay v2: HMAC-SHA256 signed form, status API, base64 data on return. Fonepay adds bank-app Dynamic QR with DV signature + txnVerification; connectIPS/NEPALPAY QR need bank/NCHL onboarding and RSA .pfx tokens.
  • Fees are not published by the major wallets — get them in writing. connectIPS has a published schedule (NPR 2/4/8 by slab); Fonepay QR payments are free for merchants.
  • International later: Stripe is unavailable to Nepal-registered businesses (needs a supported-country entity). Paddle is the pragmatic first international rail — Merchant of Record handles VAT/sales tax, subscriptions, dunning and billing support (5% + 50¢ all-in). Avoid Lemon Squeezy (shutting down 31 Mar 2027) and PayPal/Razorpay as primary rails.
  • Architecture: one gateway abstraction (initiate / verify / refund / status + capability flags) with per-provider adapters; server-side price resolution from DB; one attempt ID per checkout; DB unique constraint on (provider, provider_txn_id); idempotent webhook/event inbox; reconciliation job for pending/QR attempts; entitlements table as the single source of truth; hosted redirect keeps PCI scope at SAQ A. Verify returned amount against the stored attempt.
  • UX: checkout page → FastAPI creates attempt → redirect to provider → return page polls attempt status → unlock exactly where the learner left off, with clear failure/retry states. No gateway secret in JS.

Sources: Khalti docs · eSewa developer docs · Fonepay fees · connectIPS merchant interface · Stripe availability · Paddle pricing · Stripe webhooks

8 · Reward / retention engine
  • Evidence: gamification raises motivation/autonomy/relatedness but has little effect on actual competence (Springer 2023). Duolingo: a 7-day streak correlates with 3.6× higher course completion; a satisfying streak animation added +1.7% D7 retention; allowing two streak freezes (vs one) increased active learners +0.38% — "slack" beats rigid rules.
  • Warnings: overjustification and point-farming are documented (ACM L@S 2022, "When Gamification Spoils Your Learning"); badges/leaderboards/competitions are the elements most often linked to demotivation and anxiety (negative-effects mapping). Client-side rules are trivially patched — keep all scoring server-side.
  • Recommended engine (in FastAPI, not a heavyweight platform): append-only xp_ledger + events with idempotency keys, reward_rules (versioned, with cooldowns), streaks (freezes, timezone-aware day), mastery per skill (0–5), badges/quests, optional opt-in weekly leagues grouped by level/timezone with cooperative variants.
  • Reward learning, not activity: XP weighted by difficulty and first-attempt success, reduced for hints/retries; daily caps; anomaly detection (impossible latency, repeated payloads). Badges map to can-do statements ("ordered coffee in French", "NCLC 7 vocabulary starter") and a visible A1→B2/TEF roadmap.
  • Engines to borrow from: Gami.Fied (self-hosted XP/levels/streaks/badges/leaderboards), django-gamification, ngageoint/gamification-server — useful as architecture references, likely overkill to adopt wholesale.

Sources: Duolingo streak research · PMC systematic review · Frontiers EFL review · Gami.Fied

9 · Mascot, motion & delight
  • Why: Duo is a brand moat built on consistency and high frequency; mascots give feedback a face, softening the sting of mistakes, and anthropomorphic characters improve attitudes and affect. Duolingo spent 18 months designing a supporting cast. A mascot works as UX and as marketing — reuse it in onboarding, correct/wrong feedback, empty states, streak nudges, emails and social.
  • Tech: CSS/Web Animations for micro-interactions; sprite sheets for cheap frame animation; Lottie for rich vector celebrations; Rive for stateful interactive mascots (smaller binary, GPU 60 fps, state machines for idle/listening/celebrate/encourage/streak-risk); GSAP for sequenced DOM storytelling.
  • Low-cost plan: one distinctive original character (e.g. a "parlez" parrot / travel companion), 2–3 colours, recognisable silhouette, mini brand guide; build 5 emotion states first as SVG + CSS transforms, then port to a Rive state machine driven by reward events; add XP counters, progress fills and a streak-flame flicker, with one big Lottie celebration for milestones.
  • Hygiene: honour prefers-reduced-motion and offer an in-app "reduce animation" toggle; use GPU-friendly transform/opacity; pause offscreen animations; avoid parallax/flashes (WCAG 2.3.1/2.3.3).

Sources: Duolingo on building characters · Mascots as UX · Rive vs Lottie · web.dev reduced motion
